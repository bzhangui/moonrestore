### 最终工具链的真实 >2 GiB 流式检查

`node scripts/large-file.mjs` 实际创建 2,147,483,649 字节合成文件，备份后校验，再恢复并通过独立 Node 流式读取比较 SHA-256：

```text
97439b504cb2e2c38a52cd601e1104151606a2b97d60e8ff3298b8c004fb1087
```

| 操作 | 单次用时 | 子进程峰值 RSS |
|---|---:|---:|
| 备份 | 119,351 ms | 307,780 KiB |
| 完整校验 | 36,549 ms | 68,228 KiB |
| 恢复 | 66,942 ms | 79,792 KiB |

该样本使用 1 MiB 固定上下界分块，内容主要为零并有末尾标记，去重特征明显；不代表任意数据的吞吐或空间收益。总 RSS 包含元数据与运行时，不能由 16 MiB 缓存上限推断“恒定总内存”。64 GiB 单文件、1 TiB 单快照是 profile 拒绝阈值，未在上限规模实测。

## 受控性能探测

固定规模 8 MiB 合成文件，首次备份新增对象 8,388,608 字节；未修改再次备份新增对象 0 字节；恢复文件 SHA-256 与原文件一致。

| 操作 | 本次用时 | 子进程峰值 RSS |
|---|---:|---:|
| 首次备份 | 2,659 ms | 80,300 KiB |
| 未修改再次备份 | 1,771 ms | 77,348 KiB |
| 完整校验 | 1,422 ms | 53,084 KiB |
| 恢复 | 2,603 ms | 53,280 KiB |

这是一次本机小样本测量，不是吞吐承诺、长期生产压测或 NAS 性能结果。重跑 `node scripts/benchmark.mjs` 会记录新结果，硬件和文件系统不同可能变化。团队场景中对 1 MiB 文件插入 12 字节后复用 970,921/1,048,588 字节，约 92.6%；并非任意修改均有同等复用率。

## 证据边界和后续维护

- 当前远端结果证明所测平台和用例通过，不等于所有硬件/文件系统都兼容。
- Mooncakes 已正式发布，并在独立消费项目验证下载后的四目标检查、运行和测试；完整发布证据见 [PUBLICATION](PUBLICATION.md)。早先 dry run 本身不算发布证据。
- 故障演练采用进程终止和错误注入，不等于真实断电验证。
- 三个模拟用户场景不等于真实合作方试点。独立介质、NAS、长期运行和真实用户验证仍未完成。
- 0.1.0 不支持加密或历史垃圾回收；0.2.0 增加这两项的受限实现。两版仍不保留 ACL/时间戳/权限，也不提供数据库热备份，不能把未实现能力当作产品功能。
- 任何新增行为必须补回归测试；上游工具链变化需重新运行四目标检查及三平台 CI。
